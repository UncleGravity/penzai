# KR260 fresh-board bring-up

Validated on: Certified Ubuntu for Xilinx Devices 24.04, kernel
`6.8.0-1015-xilinx`, XRT userspace **2.18.0** (preinstalled). Background +
gotchas: memory `kr260-xrt-bringup`.

## 1. Image + access

```sh
# Flash Xilinx Ubuntu 24.04 to SD, boot
ssh-copy-id ubuntu@kria # from host
ssh ubuntu@kria # from host

# Optional: passwordless sudo (much of the flow needs root)
echo "$USER ALL=(ALL) NOPASSWD:ALL" | sudo tee /etc/sudoers.d/$USER >/dev/null
# revert: sudo rm /etc/sudoers.d/$USER
```

## 2. zocl driver

Build from XRT source matching the userspace version (2.18 = release **2024.2**).
Kernel headers (`linux-headers-$(uname -r)`) ship with the image.

```sh
git clone --depth 1 -b 2024.2 https://github.com/Xilinx/XRT
cd XRT/src/runtime_src/core/edge/drm/zocl
make                                   # builds zocl.ko against the running kernel
sudo make modules_install && sudo depmod -a
sudo modprobe zocl                     # sanity check it loads
```
Rebuild this if the kernel is ever updated (the .ko is kernel-specific).

## 3. User access to the XRT device

```sh
sudo usermod -aG render,video $USER    # else non-root XRT enumerates 0 devices
# log out / back in for it to take effect
```

## 4. Boot persistence (zocl + app auto-load)

```sh
# autoload zocl at boot
echo zocl | sudo tee /etc/modules-load.d/zocl.conf

# auto-load the PL app at boot (app + service file from step 5)
sudo cp experiments/kr260-xrt-dma-loopback/penzai-dma-loopback.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable penzai-dma-loopback.service
```

## 5. penzai TCP smokes

These validate the main repo's host/device split on the KR260 before adding PL
kernels. The scripts cross-compile `penzaid`, copy it to the board, start the
runtime over TCP, and run `penzai matmul` against it.

```sh
cp config.env.example config.env
# edit BOARD if needed; default is ubuntu@kria

# Heap-backed reference memory.
tools/kr260-fake-smoke.sh

# XRT BO-backed memory, still using the scalar reference matmul.
tools/kr260-xrt-smoke.sh
```

Expected host check:

```text
check=ok expected=16256.000 max_abs_diff=0.000000
```

## 6. CMA size (device-heap ceiling)

The XRT BO backing the penzai device heap is carved from **CMA**, so
`PENZAI_HEAP_MIB` can never exceed `CmaTotal` (`grep Cma /proc/meminfo`). The
stock image reserves `cma=800M`, which OOMs the default llama.cpp graph
(weights ~237 MiB + KV @ `-c 4096` ~448 MiB + compute @ `-ub 512` ~300 MiB ≈
985 MiB). Bump it:

```sh
# the cma value is hardcoded in the flash-kernel bootscript template (KR branch)
sudo sed -i 's/cma="800M"/cma="1536M"/' /etc/flash-kernel/bootscript/bootscr.zynqmp.kria
sudo flash-kernel        # regenerates /boot/firmware/{image.fit,boot.scr.uimg}
sudo reboot
# verify: grep CmaTotal /proc/meminfo   -> 1572864 kB
```

Ceiling is ~1.7 GB: CMA must fit the **low 2 GB DDR window** alongside the
kernel, so `cma=2048M` silently **fails** (`dmesg | grep cma:` → "Failed to
reserve" and `CmaTotal: 0` — worse than before). `1536M` is validated; leave
~128–256 MiB headroom below it for DRM/display BOs (run `PENZAI_HEAP_MIB=1280`
–`1408`). There is no plain-text `uEnv.txt`/`cmdline.txt` on this image — the
compiled `boot.scr.uimg` is the only knob.

## 7. Gotcha: kernel upgrades break zocl (keep the board pinned to 1015)

`zocl.ko` here is **hand-built** (§2) and unowned by dpkg, and the preinstalled
`xrt-dkms` (2.8.0) is obsolete: it fails to compile on any kernel ≥ 6.2
(`drm/drm_gem_cma_helper.h` was renamed to `drm_gem_dma_helper.h`). Two traps
follow:

- A kernel upgrade (e.g. `…-1029`) leaves the new package **half-configured**
  (its DKMS autoinstall fails), which blocks `flash-kernel` entirely.
- Purging `xrt-dkms` **deletes the hand-built `zocl.ko`** from
  `/lib/modules/*/updates/` — restore it with `sudo cp
  ~/XRT/src/runtime_src/core/edge/drm/zocl/zocl.ko
  /lib/modules/$(uname -r)/updates/ && sudo depmod $(uname -r) && sudo modprobe zocl`.

Stay on the validated `6.8.0-1015-xilinx`. Remove the obsolete DKMS and any
newer kernel, and protect 1015 from autoremoval:

```sh
sudo apt-get purge -y xrt-dkms
sudo apt-mark manual linux-image-6.8.0-1015-xilinx linux-headers-6.8.0-1015-xilinx
sudo apt-get purge -y linux-xilinx linux-image-xilinx linux-headers-xilinx \
                      'linux-image-6.8.0-1029-xilinx' 'linux-headers-6.8.0-1029-xilinx'
# purging the newer kernel re-runs flash-kernel for 1015 automatically
```
